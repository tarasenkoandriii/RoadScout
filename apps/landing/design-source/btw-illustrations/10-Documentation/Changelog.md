# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
versioning follows [SemVer](https://semver.org/). Per-asset version numbers
are tracked in each asset's own `manifest/*.json`
(`Manifest.md` explains how those relate to the centralized `manifest/`
folder's normalized versions); this changelog is the project-wide
narrative of what happened and why, in order.

## [Unreleased]

### Planned / flagged, not yet done
- Standalone `Warning.svg` component (currently inline-only in Privacy and
  OpenGraph — see `Architecture.md`, `Components.md`).
- A literal `pipeline/` directory automating validate→generate→optimize→
  export→preview→test→publish end-to-end, and wiring `tooling/validate.py`
  into an actual CI/CD provider (currently a real, runnable local script,
  not yet hooked into a git host's CI — see `Architecture.md`'s Asset
  Generation Pipeline section).
- Asset generation *from* a JSON manifest (currently manifests describe
  what was generated by a script; a manifest-driven generator that
  produces the SVG *from* the manifest is the reverse direction and
  doesn't exist yet).
- Automated pixel-level visual regression testing wired into CI (the
  bounding-box-check methodology in `Validation.md` is real and was used
  throughout this project's development, but runs by hand, not as an
  automated gate).

## [5.2.0] - 2026-08-03 — Audit response: JSON Schema + automated validation

### Added
- `manifest/schemas/` — three real JSON Schema (Draft 2020-12) files:
  `project.schema.json`, `tokens.schema.json`, `asset-manifest.schema.json`
  (the last one covers hero/privacy/icons/favicon/og.json's shared shape).
- `tooling/validate.py` — a dependency-free, runnable validation script
  checking manifest schema conformance, SVG structural rules (forbidden
  elements, required attributes, `<g>` nesting depth, duplicate IDs,
  color-token compliance), and file-size budgets against the actual
  shipped archive.
- `tooling/schema_validator.py` — a minimal JSON Schema validator
  implementing the subset of the spec this project's schemas actually use,
  written because the build environment has no network access to install
  the real `jsonschema` package.
- `tooling/validation-report.md` — real, captured output of a full
  validation run: 0 errors, 0 warnings, 16 findings isolated entirely to
  the explicitly-historical `03-SVG-Component-Library/` folder.

### Fixed
- `05-Icons/hero/Arrow.svg` and `Cloud.svg` were carried over from
  `03-SVG-Component-Library` without ever being updated to the current
  family's own compliance bar — both were missing `width`/`height`/
  `role="img"`/`aria-hidden="true"`. Fixed.
- The icon contact sheet (`05-Icons/previews/contact-sheet.svg` and its
  `09-Previews/` copy) used an ad-hoc gray (`#94A3B8`) for labels instead
  of the real `muted` design token (`#64748B`), and an 8-digit hex-with-
  alpha (`#ffffff22`) for cell borders that the color-compliance checker
  couldn't parse correctly. Both fixed: labels now use the real token,
  borders now use the `neutral` token at `opacity="0.13"` instead of a
  raw alpha-hex value.
- `05-Icons/sprites/sprite.svg` and `sprite-symbol.svg` were missing
  `role="img"`/`aria-hidden="true"` on their root element (the individual
  `<symbol>` children have their own `viewBox`, which was masking the
  omission from a naive substring check) — added to both.
- `manifest/project.json` was missing `09-Previews` and `10-Documentation`
  from its asset list (written before either folder existed) — updated,
  and now also references the new schemas/tooling and records this audit
  response in a new `auditHistory` field.

### Changed
- `10-Documentation/Manifest.md` and `Validation.md` updated to reflect
  that JSON Schema validation and automated checking are now real,
  runnable things, not documented intentions.

### Audit context
This release responds to `BTW-v5-Audit-and-Recommendations.md`, which
estimated ~40-50% readiness against a full v5 specification. That estimate
was computed against a snapshot of the archive that predates
`08-Favicon`, `09-Previews`, `10-Documentation`, and the centralized
`manifest/` folder entirely — most of its "missing" findings (unified
project manifest, ~70-component library, SVG sprite, PNG/WebP/ICO export,
contact sheets) were already resolved by the time the audit ran. The
genuinely open findings — JSON Schema files, and a real automated
validation pass — are what this release adds. See
`manifest/project.json → auditHistory` for the full finding-by-finding
accounting.

## [8.0.0] - 2026-08-03 — Favicon

### Added
- `08-Favicon/` — `master/favicon.svg` (512×512, solid-fill shield+wedge+
  dot design), 9 exports (favicon-16/32/48.png, favicon.ico, apple-touch-
  icon.png, android-chrome-192/512.png, mask-icon.svg,
  safari-pinned-tab.svg), manifest, README.

### Fixed
- `favicon.ico` initially embedded only one resolution instead of three
  (a Pillow API misuse — `append_images` is for multi-frame GIF/TIFF, not
  ICO; the fix was passing `sizes=[...]` directly to the base image).
- Discovered the available renderer had no transparent-background output
  mode; worked around via chroma-key alpha extraction (render on `#FF00FF`,
  convert distance-from-key to alpha).

## [6.0.0] - 2026-08-03 — Privacy Illustration

### Added
- `06-Privacy-Illustration/` — `privacy.svg` (master) + 3 variants, 9
  reusable components (Camera, Phone, Cloud, NoUpload, Shield, Route, GPS,
  Compass, FOV), manifest, previews, README.

### Fixed
- A phone→GPS connector arrow initially pointed the wrong direction
  (direction math assumed left-to-right; GPS sits to the phone's left).
- The same arrow was vertically misaligned by 30px from its intended row.
- Camera glyphs nested `<g>` three levels deep, violating the project's
  max-2 rule.

All three caught by rendering and measuring element bounding boxes, not by
reading the SVG source — see `Validation.md`'s geometric-validation
section, added specifically because of this experience.

## [5.0.0] - 2026-08-03 — Icons

### Added
- `05-Icons/` — 76 SVGs across 9 families (core/camera/detection/
  navigation/privacy/status/ui/hero/brand), 2 sprite files, contact sheet,
  light/dark preview sheets, manifests, 4-file docs set, SVGO config.
- New design tokens `danger` (#EF4444) and `muted` (#64748B), extending
  the original 5-token palette.

### Fixed
- An arc-drawing helper's `large-arc-flag` was hardcoded to 0, causing
  `status/loading.svg` and `status/sync.svg` (both needing >180° arc
  sweeps) to render nearly invisible. Fixed by computing the flag from the
  actual angle span.
- Sprite symbol IDs initially double-prefixed the camera family
  (`icon-camera-camera-ai` instead of `icon-camera-ai`).
- Discovered `<use href="#id">` alone renders blank in some WebKit-based
  renderers; fixed by always including `xlink:href` alongside `href`.
