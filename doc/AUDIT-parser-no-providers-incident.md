# Аудит: реальний інцидент — «імпорт не знаходить камер зовсім»

## Контекст

На відміну від усіх попередніх аудитів цього проєкту (P0–P3 з
`doc/TZ-parser-import-improvements.md`), знайдених і перевірених виключно в офлайн-пісочниці
без доступу в інтернет — цей інцидент виявлений **реальним користувачем на реальному
запущеному стенді** (два скріншоти `/admin/parser` і `/admin/parser/log`,
31 липня 2026, 15:50). Це найцінніший вид підтвердження: не гіпотетичний сценарій, а фактична
поведінка живої системи.

## Що показали скріншоти

1. `/admin/parser` — натиснута кнопка «Запустити всі джерела», запит
   `POST /api/admin/parser/run-all` повернув **`201 Created`, `Content-Length: 2`** — тобто
   тіло відповіді буквально `[]`, порожній масив. Таблиці «Статистика парсера по джерелах» і
   «Лог запусків» — повністю порожні, без жодного рядка (не «0 знайдено» по кожному джерелу, а
   взагалі відсутність джерел).
2. `/admin/parser/log` — «Записів не знайдено», консоль показує невдалий `fetch` для
   внутрішнього Next.js RSC-префетчу (`?_rsc=...`) — це, найімовірніше, нешкідливий шум
   dev-режиму (збігається за часом з `[Fast Refresh] rebuilding/done`), не пов'язаний з
   реальною причиною.

## Діагноз

`ScraperService.runAll()` обходить **усі** рядки `CameraProvider`
(`this.prisma.cameraProvider.findMany()`) — порожній результат `[]` означає, що в базі **немає
жодного рядка `CameraProvider` взагалі**. Перевірено прямим пошуком по всьому проєкту: жоден
SQL-скрипт (`sql/*.sql`) ніколи не створював рядки `CameraProvider` — `sql/cities-seed.sql`
заповнює `City.webcamGuruSlug` (адресу-заготовку для 5 міст: Київ/Львів/Харків/Одеса/Дніпро),
але сам `CameraProvider`, який `ScraperService.resolveAdapter()` шукає по `adapterKey`, ніколи
не створювався жодним чином — ні через seed, ні через UI.

Це **не** та сама проблема, що П0.1 (непідтверджені CSS-селектори `WebcamGuruAdapter`) — це
принципово інша, і за фактом **передуюча** проблема: без жодного `CameraProvider` парсер
взагалі не намагається щось знайти, селектори тут ні до чого. Цікаво, що сам проєкт вже мав
слід цієї прогалини — коментар у README (`doc/README.md`, розділ «Полезные команды»)
буквально казав "сначала нужно создать CameraProvider в БД", тобто прогалина була
передбачена, але ніколи не закрита скриптом.

## Виправлення

- **`sql/camera-providers-seed.sql`** (новий файл) — створює по одному `CameraProvider`
  (`adapterKey: "webcam-guru-<slug>"`) на кожен `City` із заповненим `webcamGuruSlug` через
  `INSERT ... SELECT ... FROM "City" WHERE "webcamGuruSlug" IS NOT NULL` — не хардкодить
  конкретні id вручну, підхоплює будь-яке майбутнє поповнення `cities-seed.sql` автоматично.
  Ідемпотентно (`ON CONFLICT ("adapterKey") DO NOTHING`).
- **`docker-compose.yml`** — новий сид доданий у ланцюжок запуску одразу після
  `cities-seed.sql` (потребує вже існуючих рядків `City`).
- **`doc/README.md`** — новий підрозділ «Известная проблема» з точним описом симптому (порожні
  таблиці, `[]` у відповіді `run-all`) для пошуку; інструкція з продакшн-деплою на Supabase
  тепер явно позначає цей сид як **обов'язковий, не опціональний**; застарілий коментар
  "сначала нужно создать CameraProvider в БД" у прикладах команд оновлено.

## Що потрібно зробити користувачу

```bash
docker compose down -v   # видаляє старий volume з БД без CameraProvider
docker compose up --build
```

Або, якщо не хочеться видаляти весь volume — прогнати сид вручну в контейнер, що вже працює:

```bash
docker compose exec api npx prisma db execute --file sql/camera-providers-seed.sql --schema prisma/schema.prisma
```

Після цього `/admin/parser` повинен показати 5 джерел (Київ/Львів/Харків/Одеса/Дніпро) у
таблиці статистики — і **тільки тоді** стане видно, чи актуальна проблема П0.1 (чи справді
селектори `WebcamGuruAdapter` не підходять під реальну вёрстку `webcam.guru.ua`) — до цього
моменту неможливо було перевірити навіть це, тому що парсеру не було на чому запускатися.

## Не перевірено

- Реальний прогін після виправлення (чи справді 5 провайдерів зʼявляться в таблиці, чи справді
  `run-all` тепер поверне 5 записів замість `[]`) — залежить від того, чи виконає користувач
  один із двох кроків вище; підтвердження з наступного скріншота вітається.
- Чи `webcam.guru.ua` реально має сторінки `/city/harkov/`, `/city/odessa/`, `/city/dnepr/` —
  ці три слаги (на відміну від `kiev`/`lvov`) ще не позначені як підтверджені в
  `cities-seed.sql`; після появи провайдерів для них цілком імовірно, що П0.1 (селектори)
  проявиться саме на цих трьох містах першими.
