# ТЗ: лендинг для Beyond the Wall (BTW) — Этап 1, без подписки

**Статус:** предложение к реализации
**Контекст:** маркетинговый/информационный лендинг для привлечения пользователей в
Telegram Mini App Beyond the Wall (`apps/btw`). Отдельный от самого приложения — обычный
статический/SSR сайт, задача которого объяснить, что это, и привести человека к запуску
мини-аппа в Telegram.

**Явно вне рамок этого этапа:** любая механика подписки/оплаты, платные тарифы, экран
выбора плана. Единственный CTA — открыть бесплатный мини-апп в Telegram. Монетизация —
отдельный ТЗ позже, когда/если будет решено её вводить.

---

## 1. Цель страницы

Один сценарий использования: человек переходит по ссылке (из соцсетей, рекламы, "сарафана"),
за 10–15 секунд понимает, что такое BTW и зачем оно нужно, и нажимает кнопку «Открыть в
Telegram» — это единственное целевое действие всей страницы.

## 2. Структура страницы (сверху вниз)

### 2.1 Hero-секция
- Заголовок (1 фраза) — суть продукта простым языком, без жаргона. Пример направления (не
  финальный текст): «Наведи телефон — узнай, кто может это видеть».
- Подзаголовок (1–2 предложения) — что именно делает приложение (сканирует публичные
  веб-камеры поблизости, показывает их сектор обзора).
- Основной CTA — кнопка **«Открыть в Telegram»**, ведёт на `t.me/<bot_username>/app`
  (深link мини-аппа). Единственная кнопка первого экрана — никаких вторичных CTA рядом,
  чтобы не размывать внимание.
- Иллюстрация/визуал — см. отдельное ТЗ на иллюстрации, раздел «Hero».

### 2.2 Проблема/мотивация (2–3 абзаца)
Коротко объясняет, зачем это вообще нужно — без запугивания, спокойным тоном. Ключевая
мысль: публичные камеры существуют повсюду, но у человека обычно нет простого способа
понять, какая из них реально может видеть конкретную точку — BTW закрывает именно этот
конкретный, узкий пробел.

### 2.3 «Как это работает» — 3–4 шага
Горизонтальная или вертикальная последовательность шагов с короткой подписью каждый (не
более 1 предложения на шаг) + иконка/иллюстрация к каждому:
1. Открой приложение в Telegram — без регистрации, без установки.
2. Наведи телефон вокруг себя.
3. Приложение подсвечивает камеры поблизости и их сектор обзора.
4. Если прямого совпадения нет — можно посмотреть боковые/встречные ракурсы (см.
   `doc/TZ-btw-side-reverse-view.md` — та же логика, что уже реализована в самом приложении).

### 2.4 Приватность/доверие — отдельная, заметная секция
Учитывая, что продукт по сути отвечает на вопрос «кто меня видит» — эта секция обязательна,
не второстепенна. Прямо, без юридического языка:
- Координаты пользователя не передаются на сервер как идентифицированные (тот же принцип,
  что уже реализован в режиме карты, doc/AUDIT-btw.md).
- Показываются только публичные, уже проверенные камеры — не приватные системы наблюдения.
- История сессий не хранится способом, который позволил бы кого-то отследить постфактум.
- Ссылка на полную политику приватности (если/когда она будет готова — на этом этапе можно
  оставить заглушку-якорь, не блокирует запуск лендинга).

### 2.5 Скриншоты/демо самого интерфейса
2–3 реальных (или стилизованных под реальные) скриншота из `apps/btw`: экран сканирования с
компас-стрічкой, карточка захваченной камеры, режим мини-карты. Не иллюстрации — именно
снимки настоящего интерфейса, чтобы у человека было честное ожидание того, что он увидит.

### 2.6 FAQ (4–6 вопросов)
Примеры вопросов, которые стоит закрыть заранее (снимают типичные возражения перед
переходом в Telegram):
- Это бесплатно?
- Нужна ли регистрация?
- Показывает ли приложение приватные/домашние камеры?
- Работает ли это в моём городе? (честный ответ — зависит от покрытия реестра, без
  преувеличений)
- Как обеспечивается приватность?

### 2.7 Финальный CTA + футер
Повтор той же кнопки «Открыть в Telegram» внизу страницы (для тех, кто долистал до конца, не
кликнув в hero). Футер — минимальный: ссылка на Telegram-канал/поддержку (если есть), ссылка
на политику приватности, год.

## 3. Технические требования

- **Реализация**: отдельная страница/маршрут, НЕ часть `apps/admin` (у неё уже своя
  логика авторизации/CORS, смешивать с публичным маркетинговым лендингом — усложнение без
  пользы) и НЕ часть `apps/btw` (тот — сам мини-апп, запускаемый строго внутри Telegram
  WebView, не предназначен для обычного браузерного визита). Рекомендация — отдельный
  минимальный Next.js-проект (`apps/landing` или подобное имя), деплой отдельным
  Vercel-проектом, тот же паттерн, что уже применён для `apps/admin`/`apps/btw`/`apps/api`.
- **Без бэкенда** — статическая/чисто клиентская страница, никаких обращений к API BTW не
  требуется на этом этапе (единственное "действие" — переход по deep-ссылке в Telegram).
- **Мобильная адаптация — приоритет**, не desktop: реалистичный сценарий — переход по ссылке
  именно с телефона (соцсети/мессенджеры), где и должна открыться сама кнопка в Telegram.
- **Скорость загрузки** — минимум зависимостей, никакого тяжёлого JS сверх необходимого для
  анимаций (если будут) — первый экран должен быть читаем и кликабелен мгновенно.
- **Deep-ссылка формат**: `https://t.me/<bot_username>/<app_short_name>` — тот же
  `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`, что уже используется в `apps/admin` (см.
  `doc/AUDIT-vercel-hobby.md`), плюс short_name мини-аппа, настроенный через BotFather
  (`/newapp`).

## 4. Метрики (для последующей оценки, не блокирует запуск)

- Конверсия «зашли на лендинг» → «кликнули CTA» → «реально открыли мини-апп» (последнее
  можно частично оценить через существующую телеметрию BTW — doc/AUDIT-btw.md, раздел М3).
- Откуда приходит трафик (простая UTM-разметка на кнопке, без полноценной аналитики на этом
  этапе).
