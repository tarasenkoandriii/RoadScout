# Аудит: growth-фичи (кордон, алерти, шеринг, ембед, краудсорс камер)

## Що додано (backend)

- **`src/border-crossings/`** — `BorderCrossing`/`BorderWaitReport` моделі, усереднення звітів
  по напрямку за вікном годин, rate-limit по IP, сід 7 реальних переходів (UA-PL/SK/HU/RO/MD).
- **`src/alerts/`** — `AlertSubscription`, `TelegramNotifierService` (Bot API `sendMessage`,
  той самий токен, що для логіна), два типи тригерів (зміна статусу камери / нові інциденти в
  радіусі, haversine-фільтр), `POST /internal/alerts/check` під тим самим `CronSecretGuard`,
  що вже використовується для парсера/моніторингу; доданий запис у
  `sql/pg_cron-schedule.sql` (кожні 5 хв).
- **`src/share/`** — `ShareLink`, генерація 8-символьного слага (алфавіт без 0/O/1/I/l),
  публічний резолв без авторизації, лічильник переглядів.
- **`GET /cameras/:id/embed-info`** (у `CamerasController`, публічний) — для стороннього ембед-
  віджета.
- **`src/camera-submissions/`** — `CameraSubmission`, черга модерації, `approve()` створює
  справжню `Camera` (confidence: ESTIMATED, дефолтна геометрія) + лінива, не дублююча
  реєстрація провайдера-заглушки «Краудсорс».
- Спільне: `common/client-ip.util.ts` (`getClientIp`) і `common/rate-limit.util.ts`
  (`assertIpRateLimit`/`windowStartDate`) — винесено з `home-verification`, щоб нові
  краудсорс-ендпоінти не дублювали ту саму логіку.

## Що додано (frontend)

`app/border/page.tsx`, `app/my-alerts/page.tsx`, `app/add-camera/page.tsx`,
`app/admin/camera-submissions/page.tsx`, `app/s/[slug]/page.tsx` (резолв шер-лінка + редирект),
`app/embed/[id]/page.tsx` (публічна, без `AuthGate`). У `app/page.tsx` додано: кнопку
«🔗 Поділитися», кнопку «`</> Embed`» і «🔔 Стежити» на кожній камері в результатах пошуку,
завантаження результату напряму по точці з query-параметрів `lat`/`lng`/`address` (для
переходу за шер-лінком). Нав-посилання додані на публічній сторінці та в адмінці.

## Реально прогнані тести (ts-node, справжнє виконання)

**`AlertsService`** (6 сценаріїв):
1. Зміна статусу камери ONLINE→OFFLINE → сповіщення надіслано, `lastCameraStatus` оновлено.
2. Той самий статус на наступному тику → без повторного сповіщення.
3. Видалена камера (запис відсутній у БД) → не падає, просто 0 сповіщень.
4. **Фільтр за відстанню**: інцидент за ~450м (у радіусі 1500м) — сповіщення включає його;
   інцидент за ~5.5км — виключено з того самого сповіщення.
5. Ті самі інциденти на повторному тику (не нові після `lastNotifiedAt`) → без повторного
   сповіщення.
6. **HTML-екранування** — назва підписки й заголовок інциденту з `<script>`/`<b>`/`&` у тексті
   коректно екрановані в підсумковому повідомленні (захист від зламаної Telegram-розмітки).

Усі 6 — **пройдені**.

**`BorderCrossingsService`** (4 сценарії): усереднення окремо по UA_OUT/UA_IN (перевірено
конкретними числами — (60+120)/2=90), порожня оцінка (`null`, не `NaN`) для переходу без
звітів, rate-limit по IP (429 після ліміту), валідація `waitMinutes` (відхилення 9999 хв).
Усі 4 — **пройдені**.

**`ShareService`** (2 сценарії): створення+резолв+інкремент `viewCount` (перевірено, що
рахується правильно при двох послідовних резолвах), 404 на невідомий слаг. Обидва —
**пройдені**.

**`CameraSubmissionsService`** (4 сценарії): геокодинг адреси при поданні заявки, `approve()`
створює `Camera` зі стандартними значеннями геометрії (confidence: ESTIMATED, azimuth=0/
fovAngle=90/rangeMeters=300), заявка позначається `APPROVED` з `createdCameraId`, **повторний
approve() іншої заявки перевикористовує той самий провайдер-заглушку, не створює дублікат**
(перевірено підрахунком `prisma.providers.length === 1` після двох approve()). Усі 4 —
**пройдені**.

Плюс `tsc --noEmit` над усіма новими контролерами/модулями разом з `app.module.ts` — 0 помилок,
що стосуються нових файлів (усі інші помилки — стаб-шум від пакетів, не покритих у цьому
конкретному прогоні, вже неодноразово підтверджений клас проблем у попередніх аудитах цього
проекту, не реальні баги).

## Не перевірено / відомі обмеження

> **Оновлення**: пункт нижче про "жодна з п'яти фіч не перекладена" був частково неточним —
> див. `doc/AUDIT-i18n-followup.md`. Нав-посилання та кнопки «Поділитися»/«Embed»/«Стежити»,
> додані на сторінку `/`, спочатку були захардкожені в обхід уже наявної системи перекладу — це
> була реальна регресія (сторінка `/` раніше мала компілятором підтверджену гарантію повного
> перекладу на 10 мов), знайдена й виправлена окремим аудитом. Самі сторінки-призначення
> (`/border`, `/my-alerts`, `/add-camera`, `/admin/camera-submissions`) залишаються
> неперекладеними — це й далі свідомий known gap.


- Фронтенд-сторінки (`/border`, `/my-alerts`, `/add-camera`, `/admin/camera-submissions`,
  `/s/[slug]`, `/embed/[id]`) — перевірені лише балансом дужок і вручну вичитані; повний
  `tsc`/`next build` не прогонявся (стаб `@types/react` в цій пісочниці систематично ламається
  на JSX-перевірках при повторних спробах — задокументовано в `doc/AUDIT-i18n.md`, та сама
  причина тут).
- Реальна доставка через Telegram Bot API — не перевірялась з реальним токеном/чатом (нема
  мережі в цій пісочниці); перевірена тільки внутрішня логіка (`TelegramNotifierService.send()`
  замоканий).
- П'ять нових фіч НЕ перекладені на 10 мов (див. «Мультиязычность») — інтерфейс українською/
  російською, як і адмінка. Свідомо, щоб не роздувати обсяг цього кроку — задокументовано в
  README як явний known gap.
- `/embed/[id]` успадковує кореневий `app/layout.tsx` (у т.ч. `I18nProvider`, який виставляє
  cookie мови на клієнті) — у суворому третьосторонньому iframe-контексті сучасні браузери
  можуть блокувати third-party cookie для цієї конкретної cookie; на функціональність ембеда
  це не впливає (мова там і не використовується), але не перевірено вживу.
- `sql/border-crossings-seed.sql` координати переходів — орієнтовні (центр переходу), не
  звірені з супутниковими знімками/офіційними джерелами.
