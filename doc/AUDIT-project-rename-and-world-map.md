# Аудит: перейменування проєкту (FF) + світова карта камер по країнах

> **Оновлення**: після цього кроку проєкт було перейменовано ще двічі — спершу в «Formula 1»
> (відхилено через товарний знак, див. `doc/AUDIT-project-rename-formula1-to-roadscout.md`),
> потім у **RoadScout** (поточна назва). Опис нижче — точна історія саме цього, першого кроку
> перейменування (LiveAhead → FF) і лишається без змін як історичний запис.

## Контекст

Прямий запит користувача: (1) перейменувати проєкт у "Fast & Furious" (папка `ff`),
забрендувати під тематику "Формула -1"; (2) через воєнний стан важко стартувати в Україні/
Росії — додати вкладку "карта мира" в адмінку, почати збір даних по камерах по всьому світу,
починаючи з технологічно розвинених країн, показувати кількість камер по країнах.

## Юридичне попередження (сказано користувачу до реалізації)

«Fast & Furious» — зареєстрований товарний знак Universal Pictures. Використання як назви
комерційного продукту (реальний бізнес із ФОП/платежами/крипто-обміном), особливо з тематикою
авто/трас/камер, що прямо перегукується з франшизою — реальний ризик претензій за порушення
прав на бренд. У коді використано нейтральне «FF» (просто скорочення папки), не повну назву.
Фінальний вибір публічної назви — за користувачем, з рекомендацією або іншої назви, або
юридичної консультації перед публічним запуском.

## Що зроблено

### Перейменування (обмежений, свідомо обраний обсяг)

- Папка `/home/claude/liveahead` → `/home/claude/ff`.
- `package.json` обох застосунків: `liveahead-admin`/`liveahead-api` →
  `ff-admin`/`ff-api`.
- Видимий заголовок сторінки (`<title>`) → «FF».
- Видимий текст у публічному embed-віджеті (`{camera.name} · FF`, раніше `· LiveAhead`).

**Свідомо НЕ зроблено** (обґрунтовано, не забуто): історичні згадки «LiveAhead»/«KyivCam» у
40+ вже написаних audit-/ТЗ-документах — це задокументована історія рішень, зміна яких дала б
величезний обсяг правок при нульовій практичній користі. Внутрішні технічні ідентифікатори
(наприклад, назва cookie `liveahead_lang` для збереження мови інтерфейсу) теж лишились без
змін — перейменування зламало б збережені налаштування вже наявних користувачів без реальної
потреби (це не видима користувачу назва, суто внутрішній ключ).

### Світова карта камер

- **Параметризація країни в адаптерах** (раніше жорстко закодована Україна):
  - `YoutubeSearchAdapter` — новий параметр конструктора `countryCode` (дефолт `'UA'` для
    зворотної сумісності), впливає на `regionCode`/`relevanceLanguage`/текст пошукового
    запиту (українською для UA, англійською для решти країн).
  - `GrokCameraAssistService.searchCameraPages()`/`searchAggregatorSites()` — новий параметр
    `countryName` (дефолт `'Украина'`), використовується в тексті промпту замість жорстко
    закодованого «Украина».
  - `GoogleWebCameraSearchAdapter` — новий параметр `countryName`, прокидається в
    `searchCameraPages()`.
  - `ScraperService.resolveAdapter()` — прокидає `provider.city.countryCode`/`countryName` в
    обидва адаптери (з фолбеком `'Украина'`, коли `countryName` — `null`, як для всіх
    українських міст за конвенцією схеми).
  - `AggregatorDiscoveryService.discoverForAllCities()` — прибрано фільтр `WHERE countryCode =
    'UA'`, тепер шукає для City будь-якої країни, з тим самим фолбеком на `'Украина'`.
- **SQL-сіди** — прибрано фільтр `WHERE "countryCode" = 'UA'` з
  `youtube-search-providers-seed.sql`/`web-search-providers-seed.sql` — тепер створюють
  провайдер для будь-якого City незалежно від країни.
- **`sql/cities-seed-developed-countries.sql`** — новий, явно неповний стартовий список: Нью-
  Йорк/Лос-Анджелес/Сан-Франциско (США), Берлін/Мюнхен (Німеччина), Токіо/Осака (Японія), Сеул
  (Південна Корея), Сінгапур.
- **`CamerasService.getCameraCountByCountry()`** — групування активних (не soft-deleted)
  камер по `City.countryCode`/`countryName`, з захисним фолбеком для камер без прив'язаного
  City (`UNKNOWN`), сортування за спаданням кількості.
- **Знайдена й виправлена реальна колізія маршрутів**: новий
  `GET /admin/cameras/stats-by-country` спершу був зареєстрований ПІСЛЯ вже існуючого
  `GET /admin/cameras/:id` — через це перехопився б туди як `:id` (NestJS/Express реєструють
  маршрути в порядку оголошення для того самого HTTP-методу). Переставлено перед `:id`.
- **`/admin/world-map`** — нова сторінка адмінки, табличний огляд з горизонтальними барами
  (без нової залежності картографічної бібліотеки — `react-simple-maps`/topojson тощо в
  проєкті ще немає, а проста табличка вже дає ту саму практичну відповідь на «куди рухатися
  далі»). Нав-лінк додано в `admin/layout.tsx`.

## Реально прогнані тести (ts-node, справжнє виконання)

**`getCameraCountByCountry()`** (7 перевірок): коректний фолбек `countryName` на «Україна» для
UA-міст (де `City.countryName` — `null` за конвенцією); реальний `countryName` з City
використовується напряму для інших країн; **soft-deleted камера коректно виключена з
підрахунку** (виявлена й виправлена помилка тестового фікстуру — `!where.deletedAt`
неправильно трактує `null` як «фільтр відсутній» у JS; підтверджено, що сама реалізація
коректна); захисне групування камер без City як `UNKNOWN` (не падає, не губить з підрахунку);
сортування за спаданням; сумарна кількість по групах точно збігається з кількістю активних
камер.

**Параметризація країни в `YoutubeSearchAdapter`** (5 перевірок): виклик без явного параметра
країни — поведінка ідентична попередній (регіон `UA`, український текст запиту) — зворотна
сумісність підтверджена; виклик з `countryCode: 'US'` — коректно `regionCode=US`,
`relevanceLanguage=en`, англійський текст запиту замість українського.

Разом **12 нових перевірок**, усі пройшли (з двома реальними помилками тестового фікстуру,
знайденими й виправленими під час тестування — не помилками самого коду). Плюс
`tsc --noEmit` по всьому графу застосунку — 0 помилок у змінених файлах (2 залишкові — той
самий, вже неодноразово підтверджений артефакт спрощеної заглушки типів у
`lookahead.controller.ts`/`monitoring.controller.ts`).

## Не перевірено / відомі обмеження

- **Реальний прогін `prisma db push`** з новим сідом міст — не перевірявся проти живої БД.
- **Фокус на клієнтах/мобільних камерах-міні-апп** (друга частина оригінального запиту) — НЕ
  реалізований у цьому кроці: формулювання надто розмите («особливо приділяючи увагу
  клієнтам»), щоб визначити конкретну технічну зміну без додаткового уточнення — які саме
  покращення клієнтського досвіду/Telegram Mini App для рухомих камер (FIXED_ROUTE) мались на
  увазі.
- **Реальний збір даних по нових країнах** — сама інфраструктура (адаптери, сіди) готова й
  протестована, але жодного реального проходу парсера по нових містах не виконувалось (немає
  мережі в пісочниці) — якість/повнота результатів для не-українських міст не перевірена.
- Список міст технологічно розвинених країн — явно неповний стартовий набір (по 1-3 міста на
  країну), розширення — окрема, менш термінова робота.
- Фронтенд-зміни (`/admin/world-map`, нав-лінк) — перевірені балансом дужок і вручну
  вичитані, не прогонялись через `tsc`/візуально в браузері (та сама, вже неодноразово
  задокументована причина нестабільності заглушки `@types/react` у цій конкретній пісочниці).
