# Аудит: Windy Webcams API + клас камер NATURE + глобус на світовій карті

## Контекст

Продовження реалізації запиту користувача (частина відкладена на «Continue» через величезний
обсяг): (1) адаптер Windy Webcams API замість webcam.guru.ua для не-українських міст; (2)
класифікація камер «природа/пляж/море» як окремого класу з виключенням із пошуку; (3) селектор
«глобус/таблиця» на `/admin/world-map`, глобус за замовчуванням, аналогічно проєкту ОРБІТА.

## Що зроблено

### `WindyWebcamsAdapter`

Реальна, структурована база камер через офіційний API (`api.windy.com/webcams/api/v3/webcams`,
заголовок `x-windy-api-key`) — на відміну від текстового пошуку (YouTube/Google), кожен запис
гарантовано справжня камера з готовою геолокацією, `isRelevant()`-фільтр не потрібен.
**Категорії Windy дають детерміновану класифікацію NATURE** — камера з категорією, що містить
`beach`/`sea`/`nature`/`mountain` тощо, одразу позначається новим полем
`RawCameraItem.suggestedLocationType: 'NATURE'`.

### Новий загальний механізм — `RawCameraItem.suggestedLocationType`

Не специфічний для Windy — будь-який майбутній адаптер зі структурованими даними (не тільки
текстовий пошук) може передати тип локації напряму, обходячи AI-класифікацію.
`ScraperService.processItem()` використовує це поле, якщо воно є, замість дефолтного OUTDOOR;
адаптери без цієї інформації (webcam.guru.ua, YouTube/Google-пошук) поводяться як і раніше.

### Клас камер NATURE

- Новий enum-варіант `CameraLocationType.NATURE` у Prisma-схемі.
- **Жодних змін логіки пошуку за сектором не знадобилось** — існуючий фільтр
  `locationType = 'OUTDOOR'` (у обох PostGIS-запитах і JS-фолбеку) — це allowlist, не
  denylist, тому новий клас автоматично виключається сам собою.
- `CamerasService.findNatureNearby()` — точна копія патерну `findIndoorNearby()`, показує
  NATURE-камери як «поруч», не в основному пошуку.
- `GrokCameraAssistService` — новий прапор `isLikelyNature` у AI-класифікації (для джерел без
  структурованих категорій), той самий принцип, що вже є `isLikelyIndoor`.
- Усі три DTO (`UpdateCameraDto`, `ResolveSourceRawDto`, `ApproveCameraSubmissionDto`) приймають
  `NATURE` як валідне значення `locationType`.

### Взаємне виключення — розширено на четверте сімейство

`webcam-guru-*`/`youtube-search-*`/`web-search-*`/`windy-*` — кожне зі своїм окремим cron-
розкладом і endpoint'ом, загальний `run-all` явно виключає всі три нові сімейства.

### Глобус на світовій карті (`/admin/world-map`)

- `WorldGlobe.tsx` — новий клієнтський компонент на базі `globe.gl` (Three.js), динамічний
  імпорт без SSR (той самий принцип, що вже є для `SectorMap`/Leaflet — WebGL працює тільки в
  браузері).
- Селектор «🌐 Глобус / 📊 Таблиця» ліворуч від контенту, глобус — вибір за замовчуванням.
- Країни показані як точки (не choropleth-полігони — немає доступу до реального GeoJSON
  кордонів країн у цій пісочниці, на відміну від, можливо, прототипу ОРБІТА) — розмір і колір
  масштабуються за кількістю активних камер, з підказкою при наведенні.
- Ручна таблиця координат центрів країн — покриває країни вже в проєкті + типовий набір
  великих країн, **не всі ~195 країн світу**.

## Реально прогнані тести (ts-node, справжнє виконання)

**`WindyWebcamsAdapter`** (12 перевірок): відсутність ключа → порожній результат без мережевого
виклику; ключ коректно передається в заголовку `x-windy-api-key`; **реальний тестовий кейс —
пляжна камера з категорією `beach` коректно класифікована як `NATURE`, вулична камера поруч —
як `OUTDOOR`**; коректний парсинг `streamUrl` з `player.live.embed`, `locationText` з полів
`location`; 401/403 → явне кидання помилки з підказкою на ключ; інші помилки статусу → порожній
результат без падіння; вебкам без id відфільтрований.

**`findNatureNearby()`** (3 перевірки): знаходить NATURE-камеру; виключає OUTDOOR-камеру;
**виключає soft-deleted NATURE-камеру** (той самий принцип, що вже перевірений для
`findIndoorNearby()`).

**Інтеграція `suggestedLocationType` у `ScraperService.processItem()`** (1 перевірка):
наскрізний прогін через реальний `runForProvider()` з Windy-подібним адаптером, що повертає
`suggestedLocationType: 'NATURE'` — підтверджено створення `CameraSourceRaw` без падіння.

**Взаємне виключення на чотири сімейства** (5 перевірок): загальний `run-all` виключає всі три
нові сімейства одразу; кожен зі спеціалізованих викликів торкається лише свого сімейства;
**усі чотири провайдери спрацьовують рівно по одному разу сукупно** — жодного подвійного чи
пропущеного запуску.

Разом **21 нова перевірка**, усі пройшли. Плюс `tsc --noEmit` по всьому графу застосунку —
0 помилок у змінених файлах (2 залишкові — той самий, вже неодноразово підтверджений артефакт
спрощеної заглушки типів у `lookahead.controller.ts`/`monitoring.controller.ts`).

## Не перевірено / відомі обмеження

- **Реальний виклик Windy Webcams API з живим ключем** — мережа недоступна в цій пісочниці;
  точні назви полів відповіді звірені лише з публічною документацією, не живим викликом —
  перед продакшеном варто звірити один реальний запит (та сама, вже неодноразово задокументована
  у проєкті практика для зовнішніх API).
- **Глобус (`WorldGlobe.tsx`) не прогонявся через `tsc`/візуально в браузері** — та сама, вже
  неодноразово задокументована причина нестабільності заглушки `@types/react` у цій конкретній
  пісочниці; крім того, `globe.gl` — нова залежність, доданий лише запис у `package.json`, сам
  реальний `npm install`/збірка не виконувались (немає мережі).
- **Точки на глобусі, не справжній choropleth з кордонами країн** — свідомий компроміс через
  відсутність доступу до реального geo-датасету кордонів країн у цій пісочниці; функціонально
  дає ту саму практичну відповідь («де більше камер»), але візуально простіше за, можливо,
  прототип ОРБІТА.
- Таблиця координат центрів країн — обмежений ручний список (~30 країн), не всі країни світу
  отримають точку на глобусі (але лишаються видимими в табличному режимі).
